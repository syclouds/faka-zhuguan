### 原始需求复述

> 帮我改成安卓 APK 文件，同时允许你在桌面-法考文件夹内，找到 2026 年相关法考资料做参考。

即：① 把现有微信小程序「法考主观题速记」改造成可安装到安卓手机上的 APK 应用；② 参考 `C:/Users/1/Desktop/法考/2026` 下的 2026 年法考资料，校准并强化应用内容。

## 一、产品目标

把已跑通的「法考主观题速记」微信小程序（88 个结构化考点 + 8 套论述模板 + 采分点默写 + 艾宾浩斯复习队列）**完整移植为一个可离线安装的 Android APK**，使考生摆脱微信环境，在通勤、午休等碎片场景用单手完成"背—默写—标记"闭环；同时把小程序的历史遗留短板补上。

在此基础上，参考桌面 2026 年法考资料做**内容增量**：本次抽样确认的最大空白是"只背不练"——资料中大量存在「命题场景（案情 → 设问 → 采分点答案）」「小案例训练」「背诵口诀」「法条索引」「设问类型答题模板」五类结构化内容，小程序一个都没有。本次改造应把这些**结构化提炼为自有表述**后接入 App，让产品从"记忆工具"升级为"记忆 + 练题"的最小闭环。

> 涉及考试日期、科目分值、报名政策等表述，一律以司法部官方公告为准，App 内需显式标注。

## 二、关键约束

| 编号 | 约束 | 说明 |
|---|---|---|
| C-1 | **本机无 JDK / Android SDK / Gradle**（已勘察确认，`java`、`gradle`、`ANDROID_HOME` 均不存在） | 团队**禁止**交付"需要用户自己装 JDK+Android Studio 才能编译"的裸 Gradle 工程。 |
| C-2 | 可用工具链仅 Node.js v24.15.0 + npm 10.9.7 + Python（pypdf / python-docx） | 意味着所有产物必须由 Web 技术栈生成，APK 的"壳"必须走**云端构建**或**免本地工具链**路径。 |
| C-3 | 微信能力在安卓上全部不可用 | `wx.login` / 云开发 / `wx.setStorage` / 订阅消息 / `wx.share` 均需降级替代（见需求池 C 组）。 |
| C-4 | 版权合规 | 桌面资料为第三方培训机构付费讲义，**不得原文大段复制进代码仓库**；只允许结构化提炼为自有表述的卡片、口诀、索引，并在 App「关于」页声明内容来源性质与免责声明。 |
| C-5 | 资料质量参差 | 40 份 PDF 中多数为扫描图片版（无文本层），文本可提取的仅少数（见第七节抽样结论）。内容增量必须**优先基于可提取文本的那几份**，不要在 OCR 上投入预算。 |
| C-6 | 内容时效性 | 法规逐年更新（如《公司法》2023 年修订、《行政复议法》2023 年修订），卡片 `level: 'S'` 需在每轮备考前复核。 |

### 对 C-1 的产品层面主张（重要，请架构师严格遵守）

1. **交付物 = "工程 + 一键云构建流水线"，而不是"工程 + 一份让你自己配 JDK 的 README"。** 用户拿到手后，成功拿到 APK 的路径必须 ≤ 3 步，且**全程不需要在本机安装任何工具链**。
2. **推荐主方案：Capacitor 7 + GitHub Actions 云构建。** 我们把 Web 产物 commit 进仓库，仓库内置 `.github/workflows/build-apk.yml`；GitHub 托管 Runner 自带 JDK 17 + Android SDK，跑一次 workflow 即可在 Artifacts 下载已签名的 `app-debug.apk`（Release 签名可通过 repository secret 配置）。用户只需：① 建仓库并 push → ② Actions 页面点 Run workflow → ③ 下载 APK。
3. **备选方案（P1）：PWA「添加到主屏幕」。** 同一个 Web 产物配 Service Worker + Web Manifest，用户用手机 Chrome 打开网址 → 添加到主屏幕 → 图标、全屏、离线可用。**零构建、零审核、当场可用**，作为 GitHub 不可用时的兜底体验（它满足"装到手机、离线、有图标"的实质诉求，但不是 APK 文件形态）。
4. **备选方案（P2）：第三方云打包服务**（如 HBuilderX 云打包）上传 Web 产物出 APK。作为用户无 GitHub 账号时的兜底，在文档里给出操作指引即可，本次不实现。
5. **明确禁止的交付形态**：只给一个 `android/` 目录 + "请先安装 JDK 17 和 Android SDK"。若架构师评估后认为云端构建路径不可行，**必须提前上报 team-lead，不得静默降级**。
6. **WebView 能力边界**：所有功能必须能在 Android 8+ 的 Chrome/WebView 90+ 中运行，**不得依赖任何微信 JSAPI**。构建产物默认不申请网络权限也能完整使用（内容全部内置离线）。

## 三、用户故事

1. **作为**在职备考、每天只有通勤时间背书的考生，**我希望**把 App 装到手机桌面、打开就能背、不用先打开微信再搜小程序，**以便**在地铁没信号的路段也能完成今日复习队列。
2. **作为**已经背完 88 个考点、但一到真题就写不出采分点的考生，**我希望**App 里有「命题场景 / 小案例」题：先看案情和设问，自己口述要点，再展开参考答案并逐条自评是否踩中，**以便**把"认得"变成"写得出来"。
3. **作为**被刑诉各种数字和情形搞混的考生，**我希望**有一张「口诀卡」列表，每条口诀短到能念出来（如"显著轻、过时效、特赦、告诉和死掉"），点开能看到它对应的完整情形和法条条号，**以便**在考场上靠一句口诀把六项情形全部勾出来。
4. **作为**答题时不知道该写多少、怎么组织的考生，**我希望**在练题前先看到"这道题属于哪类设问（救济类 / 方案类 / 是非评价类 / 纠错类 / 简答论述 / 开放式）"以及该类设问的标准答法结构，**以便**按模板组织语言，不漏"结论 + 依据"的结构分。
5. **作为**换了新手机或重装了 App 的考生，**我希望**能把学习进度（掌握度、复习队列、错题本、打卡）导出成一个文件保存下来，换机时导入恢复，**以便**不因为换设备丢失连续打卡记录和复习节奏。
6. **作为**单手扶地铁扶手背书的考生，**我希望**"没记住 / 有点模糊 / 记住了"三个按钮和默写输入框都落在屏幕下半部的拇指热区、顶部只放只读信息，**以便**全程单手完成一轮背诵。

### B 组｜2026 资料带来的内容增量（**均基于第七节实际抽样结果**）

> 合规要求：全部为**结构化提炼后的自有表述**，不复制讲义原文段落；每条新增内容标注"依据 2026 年公开备考资料整理，以司法部官方公告与现行有效法律法规为准"。

| 编号 | 需求描述 | 优先级 | 验收标准 |
|---|---|---|---|
| B-1 | **新增「口诀卡」模块与卡片类型 `mnemonic`**：结构 `{ id, subject, chapter, mnemonic(口诀短句), scenario(适用情形标题), points:[{k,v}], clauseIndex(法条号), level }`。首批用**刑诉**打样（抽样资料含 100+ 条编号口诀，每条自带展开表述与法条索引），后续科目同结构扩展 | P0（刑诉打样） | 刑诉口诀卡 ≥ 60 条；列表页可按章节/搜索筛选；卡片正面只显示口诀短句，翻面显示完整情形 + 法条号；口诀卡可进入与考点卡相同的艾宾浩斯复习队列 |
| B-2 | **新增「法条索引」反向速查**：以口诀/案例答案中出现的法条号（如《刑诉法》第 16 条、《刑诉解释》第 98 条）为索引键，建立"法条号 ↔ 相关卡片/口诀/案例"双向跳转 | P1 | 背诵卡、口诀卡上的法条号可点击 → 打开法条速查页，列出该条号关联的全部卡片；搜索框支持输入"刑诉法 16"直达 |
| B-3 | **新增「案例训练」模块（补"只背不练"的最大空白）**：结构 `{ id, subject, chapter, level, prompt(案情), questions:[{ q, answer, scorePoints:[...], clauseIndex }] }`。流程：先看案情+设问 → 用户自述/草稿 → 展开参考答案（采分点逐条）→ 逐条自评"答到/没答到" → 未答到的采分点自动进错题本 | P0 | 首批覆盖 ≥ 3 个科目、≥ 30 问（抽样资料：刑诉小案例 279 页、民法采分有料 108 页、法治思想大案例均有题+解析配对）；自评结果计入"我的 → 掌握度分布" |
| B-4 | **新增「设问类型答题模板」页**：把资料中的 6 类设问（救济类 / 方案类 / 是非评价类 / 纠错类 / 简答论述 / 开放式）× 对应答法结构（如"结论 + 依据""先评价 + 三段论""大前提 + 小前提 + 结论"）做成一张可随时查的速查表 | P1 | 6 类齐全，每类含：识别特征、示例设问、标准答法结构、常见失分提示；可从案例训练页一键跳转查看当前设问所属类型模板 |
| B-5 | **法治思想考点细化**：现有 12 张卡的"十一个坚持"每条只有 1 行 core，资料中每条坚持有 4–6 个子要点；需拆分为子采分点。另补充现有卡片**缺失章节**：资料中的「实践要求——发挥法治在经济社会发展的保障作用」「正确处理全面依法治国的重大关系」 | P1 | "十一个坚持"每条子要点 ≥ 3 条；新增 ≥ 2 个章节卡片；法治思想总卡片数由 12 增至 ≥ 16 |

| B-7 | **现有 88 卡与 2026 资料对账**：逐科比对章节覆盖，标出资料中有、App 中没有的考点缺口，补录为卡片 | P1 | 产出一份 `docs/content-gap.md` 对账表（科目 / 资料章节 / App 现状 / 是否补录）；至少完成刑法、刑诉、民法、法治思想四科对账 |
| B-8 | **内容版本与免责**：新增「关于/免责」页，声明内容整理自公开备考资料与现行法律法规、非官方发布、分值/日期/政策以司法部公告为准 | P0 | App 内可见；首次启动弹窗确认一次 |

| C-6 | 分享/反馈：微信分享 → 安卓系统分享（系统分享面板）；新增"意见反馈"跳转邮件 | P2 | 系统分享面板可拉起；反馈入口可见 |

## 五、UI 设计稿描述（竖屏手机，单手场景）

### 整体框架（与小程序版差异）

| 项 | 小程序版 | Android 版 |
|---|---|---|
| 底部导航 | 微信原生 tabBar（固定、不可自定义高度） | **自绘底栏**：4 个 Tab（考点/背诵/口诀/我的），高度 56dp + `safe-area-inset-bottom` 自适应（手势导航机型增高），选中态为图标+文字变色 + 顶部 2dp 指示条。**论述页从底栏移入「考点」页顶部二级 Tab**（为新增口诀模块腾位） |
| 顶部栏 | 微信胶囊 + 原生标题 | **自绘 AppBar**：高 56dp + 状态栏高度（沉浸式，状态栏文字自动反色）；左侧返回箭头（根页面无）、居中标题、右侧溢出菜单（搜索/设置） |
| 返回 | 小程序右上角/微信系统返回 | **系统物理/手势返回键接管**，维护页面栈（见 A-4） |
| 屏幕方向 | 跟随微信 | **锁定竖屏**（A-8） |

### 页面清单

**P1 考点（首页，根页面）**
- AppBar：标题「法考主观题速记」，右侧搜索图标
- 倒计时卡：距考试还有 N 天（可自定义日期，默认空并提示设置；标注"以司法部官方公告为准"）
- 今日任务卡：待复习 N / 待新学 N（受每日新学上限控制）+ 连续打卡 N 天 + 大号「开始背诵」按钮
- 顶部二级 Tab：考点 / 论述（原底栏「论述」在此收拢）
- 科目卡片网格：7 科，每科显示「科目名 · N 卡 · 章节数」+ 掌握度进度环
- S 级必考速览横向滑动条

**P2 背诵（底栏 Tab 2）**
- 顶部四 Tab：今日 / 错题 / 收藏 / 全部
- 卡片列表（标题 + level 徽标 + 下次复习日期）
- 右上角「每日新学上限」设置入口

**P3 背诵卡（核心页，全屏沉浸式）**
- 上半屏（只读区）：考点标题（大字）+ level 徽标 + 所属章节面包屑
- 中部：状态机三态 —— ① 仅标题（自问自答）→ ② 翻卡（核心 + 采分点 + 法条 + 易错提示）→ ③ 采分点默写（关键词挖空输入，自动判定命中）
- **下半屏（拇指热区）**：三档掌握度按钮「没记住 / 有点模糊 / 记住了」，横向三等分、高度 ≥ 56dp，固定在屏幕底部（含安全区）
- 口诀卡复用同一页面，仅把"标题"换成口诀短句、"采分点"换成完整情形列表

**P4 口诀（底栏 Tab 3，新增）**
- 顶部科目筛选（首批仅刑诉可选，其余置灰显示"待补充"）
- 口诀列表：口诀短句为主标题、字号偏大便于朗读；副标题为适用情形
- 点击进入 P3 背诵卡（口诀模式）；口诀卡上的法条号可点 → 法条速查页（B-2）

**P5 案例训练（新增，入口：考点页科目卡右上角"练" + 我的页）**
- 列表：科目筛选 + 案例卡（标题 + 难度 + 完成状态）
- 详情页：案情（可滚动长文本，支持字号调节）→ 设问列表 → 每个设问下：「写下你的要点」多行输入框（草稿，自动保存）→ 「查看参考答案」展开（采分点逐条列出，法条号可点）→ 每条采分点两个按钮「答到 / 没答到」→ 顶部显示本题踩中率

**P6 设问类型答题模板（新增，从 P5 设问旁「怎么答？」入口进入）**
- 6 类设问的卡片列表：类型名 + 识别特征 + 示例设问 + 标准答法结构 + 常见失分提示
- 支持从 P5 传入设问类型时自动高亮定位

**P7 论述模板详情**
- 与小程序一致：框架 / 万能金句（勾选已背）/ 可替换槽位 / 示范段落 / 失分点 / 答题草稿练习

**P8 我的（底栏 Tab 4）**
- 掌握度分布（含案例训练自评结果）、近 7 天学习柱状图
- 设置：每日新学上限、考试日期、提醒开关与时间（C-5）、深色模式（A-10）、字号
- **数据：导出备份 / 导入恢复**（C-2，本次替代云同步）
- 错题本、收藏、自建考点、案例训练记录
- 关于与免责声明（B-8）、版本号

**P9 全文检索**：搜索框 + 结果分组（考点 / 口诀 / 案例 / 论述模板 / 法条号），支持"刑诉法 16"这类条号直达（B-2）

### 关键交互规范
- 三档掌握度按钮常驻屏幕底部，任何滚动状态下不被遮挡
- 默写输入框聚焦时，软键盘弹起不遮挡输入框与三档按钮
- 所有列表项高度 ≥ 48dp，满足触摸目标尺寸

### 结论（内容增量的现实依据）

1. **最大空白确认：App 只有"背"，没有"练"。** 资料里命题场景/小案例/大案例占比最大，且**题干与解析成对**，可直接结构化成"案情 → 设问 → 采分点答案 → 自评"的训练卡。README 自己也把"主观题案例题库 + 采分点自评"列为第一可扩展方向。→ **B-3 立为 P0**。
2. **口诀是现有卡片完全没有的第二种记忆载体。** 现有 88 卡结构是"标题 + 采分点"，适合理解记忆；口诀适合"一句话唤起一串情形"的考场提取。且向高甲口诀 100+ 条自带法条索引，可直接撑起刑诉一科。→ **B-1 立为 P0（刑诉打样）**。
3. **法条索引可以低成本反向构建**，不必攻 OCR：口诀与案例答案中大量出现 `【法条索引】（《刑诉法》第 16 条）` 这类结构化标注，直接抽取即可。→ **B-2 立为 P1**。
4. **6 类设问答题模板是"低投入高回报"项**：一张表就能教会用户"这类问法该怎么组织答案"，且资料中已经成表。→ **B-4 立为 P1**。
5. **现有 88 卡颗粒度偏粗**：法治思想"十一个坚持"每条仅 1 行，资料中每条有 4–6 子点；且缺「实践要求」相关章节。→ **B-5/B-7 立为 P1**。
6. **不要为扫描件花预算**：40 份中约 2/3 无文本层（含 72MB 的刑法带背）。应优先把 5 份可读资料吃透打样。→ 对应 Q5 推荐值。
